# Pendiva recording handoff

Use this checklist to record the English, fictional-data walkthrough. The local UI and browser journey could not be opened from the verification sandbox because its socket policy blocks localhost access; startup and database seeding were verified. Confirm the visible UI before recording.

## Start the isolated demo

From the repository root in PowerShell, use a new database filename if you want a clean recording state:

```powershell
python -m scripts.iniciar_demo --demo --demo-language en --demo-no-finance --demo-db data/pendiva-hackathon-en.sqlite3
```

The command seeds nine fictional conversations and starts the local panel and isolated webhook receiver. The demo initializer is idempotent. It does not send a WhatsApp message or call Meta AI automatically. A Pendiva question calls AI only after you check the visible consent. Stop both services with `Ctrl+C`.

**Supported Python:** 3.12 or newer.

## Configuration and demo login

- The local panel needs no extra Python packages; the Pendiva AI part of the walkthrough requires a working `MODEL_API_KEY` in `.env`.
- Sign in with demo@pendiva.local and demo-password-local-2026 (also printed by the launcher). The launcher re-synchronizes this fictional account password when seeding, including for an existing demo database. Restart the launcher to clear its temporary login throttle.
- For an assistant answer, configure `MODEL_API_KEY` in the ignored local `.env` and confirm the on-screen consent before submitting. The key's current validity and Meta connectivity were not verified in this sprint. A live request may consume credits.
- `PENDIVA_COOKIE_SECURE=1` is only for HTTPS; leave it unset for this localhost demo.
- WhatsApp, ElevenLabs, and finance import are optional. The scripted path does not require WhatsApp or ElevenLabs. Import the included fictional CSV only if showing the sales chart.
- Do not display `.env`, terminal history beyond the printed demo credentials, browser notifications, personal chats, or real customer data.

## Recommended story

- **Customer:** Ana Rojas, fictional.
- **Opportunity:** Deep sofa cleaning, pending confirmation before a quote.
- **Evidence:** Ana's messages state that she wants a three-seat sofa cleaned in Chapinero this week and asks for a quote. The recommendation is to confirm the service address and preferred date before preparing the quote.
- **Human review:** Show the evidence and the review/edit controls. Do not claim that the customer was ignored, that a quote was sent, or that revenue was earned.
- **Commitment:** Carlos Díaz asks about Saturday morning availability. The fictional advisor message says, “I will check the schedule and confirm tomorrow.” Its role is explicitly seeded as business-advisor authored. The original relative timing is preserved; no exact due date is inferred. Fulfillment starts unverified, which does not mean the promise was broken.

## Screens and Pendiva question

1. Keep the interface in English. Start on **Overview** and show the **Needs Attention** queue briefly.
2. Open **Customers → Ana Rojas**. Show the Decision Brief, the saved fictional-example label, missing exact address and unconfirmed Thursday availability, suggested action, and one clickable source message.
3. Select **Carlos Díaz**. Show the advisor-authored promise, “Tomorrow” as stated, source message, and **Not verified**. Point to **Confirm fulfillment** and **Dismiss commitment** without clicking; this is a fictional example, not an automatic Pendiva detection.
4. In the assistant, check the consent box first. It discloses that the question, business context, up to 36 relevant message excerpts, and up to 3 previous questions go to Meta AI; this may use credits. Then click **Start voice conversation** and allow microphone access if prompted. Ask aloud:

   > What information is still missing before I can quote Ana Rojas, and what should I ask her next?

5. Stop speaking and wait. Pendiva submits after 10 seconds without new recognized speech. Let it speak the answer; show its citations/coverage and the speaker icon beside the answer. Click that icon only if you want to replay the answer.

6. Review Pendiva's AI-generated answer, cited saved messages, and coverage note. The answer is generated by the configured Meta AI service; check that it matches its sources.

7. Optionally select **Prepare reply**. Show the editable draft; it is not sent. Save it only if you want to show that action.

8. Close with: “Traditional CRMs remember customers. Pendiva helps businesses remember their commitments.”

## Before showing a Pendiva voice turn

Test the microphone, browser speech recognition, Meta AI key, and one written Pendiva question before recording. If microphone recognition fails, type the same question and click **Ask Pendiva** after confirming consent.

The browser may send microphone audio to its speech-recognition service. Pendiva sends the transcript and bounded context to Meta AI only after consent. The 10-second timer resets if more speech is recognized. Each answer has a speaker icon. The mic and speaker depend on browser/device support.

For a typed Pendiva question, use:

   > What do I need to know before replying to Ana Rojas? What is known, what is missing, and what should I do next? Cite the stored messages.

The current assistant does not retrieve commitment records; do not ask it to enumerate all commitments.

## If browser voice recognition is unavailable

Use the typed Pendiva question instead. Meta AI still needs a working key and the same explicit consent.

## Known limits and freeze identifier

- The demo data is fictional and covers only seeded conversations. The WhatsApp sandbox does not backfill old chat history.
- The owner assistant searches saved messages locally, then sends the question, business context, up to 36 relevant sources, and up to 3 recent assistant questions to Meta AI after explicit consent. Voice capture uses browser recognition, waits for 10 seconds of silence, then sends the transcript to Pendiva AI and reads the answer with device speech synthesis.
- Login throttling is process-local; tenant isolation, retention/deletion, production authentication, and deployment are not production-certified.
- A 24-case bilingual fixture exists but was not used to claim assistant accuracy.
- Carlos's commitment is a synthetic seeded example reviewed through the existing recommendation controls. Live AI commitment extraction, dedicated commitment records, automatic due-date resolution, and commitment-aware assistant retrieval are deferred. A live AI request is not evidence of commitment extraction.
- **Application freeze commit:** `14c05da` (`Make Pendiva voice assistant hands-free`). The recording instructions in this handoff are committed immediately after that code freeze; the final repository HEAD is reported in the delivery message.
- **Video recording and upload:** not performed; the project owner records and supplies the actual URL.
